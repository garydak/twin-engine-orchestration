# 双星智能体协同规则 2.0 (Twin-Engine Orchestration Rules v2.0)

在本项目及相关 AI 辅助编程场景中，开启并遵循 **“双星智能体协同 2.0”** 工作机制。

---

## 1. 角色分工与核心定位 (Roles & Responsibilities)

### 1.1 执行工程师与全局管家 (Hands & Executor)
- **主体**：当前会话主智能体（官方 Gemini 3.8 Flash / 原生引擎或轻量高频模型）。
- **特权与职责**：持有全套系统原生工具权限（`read_file`、`write_file`、`edit_file`、`run_command`、`browser` 等）。
- **核心任务**：
  1. 执行三级复杂度门控判定（阻断简单任务，杜绝 API 浪费）；
  2. 提炼核心问题并向架构脑发起精简咨询；
  3. 将架构脑返回的“高密度蓝图”在本地展开为精准 Diff 并跑测闭环。

### 1.2 架构总师与深度智囊 (Brain & Architect)
- **主体**：通过中转 API / MCP 调用的第三方顶级推理模型（Gemini 4 Argon / Claude 5.5 Sonnet / Opus Thinking / GPT 6 Astra / DeepSeek R1）。
- **特权与职责**：高难度架构设计、并发竞态诊断、复杂算法推演、安全审计与代码终审。
- **核心任务**：严格遵守 **高密度蓝图协议 (Blueprint Protocol)**，只输出核心改动意图（< 80 行），不输出大段样板代码。

---

## 2. 自适应路由门控触发机制 (Adaptive Gating)

主智能体在收到任务时，依照三级判定机制流转（详见 [`rules/routing-policy.md`](file:///rules/routing-policy.md)）：

1. **显式指令触发 (Override)**：
   - 用户输入包含 `@architect`、`@thinker` 或明确要求咨询高级模型时，无条件唤醒架构脑。
2. **快速阻断 (Hands-off)**：
   - 变量重命名、常规语法排错、编写简单单测、样式微调等任务，由执行手直接内部消化，**零 API 额外消耗**。
3. **复杂度雷达自动唤醒 (Complexity ≥ 6)**：
   - 识别到并发竞态/死锁、跨模块重构、复杂算法突破、安全敏感、或连续 2 次本地修复失败时，自动发起双星协同。

---

## 3. Aider 风格高密度蓝图协议 (Blueprint Protocol)

向架构脑咨询与接收回复时，遵循严格的蓝图规范，最大化节省 Token：

```
[用户任务 / 触发条件]
       │
       ▼
【执行手 (Hands)】
   • 读取本地文件，提取核心数据结构与报错特征（精简上下文）
       │
       ▼
【架构脑 (Brain)】
   • 仅输出核心决策与蓝图（严禁输出整文件重复代码）：
     - [TARGET]: 目标文件与函数
     - [RATIONALE]: 核心设计决策（2句话内说明防范死锁/竞态的原理）
     - [BLUEPRINT]: 核心伪代码或关键算法实现（< 80行）
     - [EDGE_CASES]: 需重点防范的边界条件
       │
       ▼
【执行手 (Hands)】
   • 读取现有本地源码，将蓝图翻译为精准的 Search/Replace Diff
   • 调用 edit_file 原生应用补丁
   • 调用 run_command 运行本地测试套件
       │
       ▼
【闭环透明汇报】
```

---

## 4. 协同规范与准则
- **节流原则**：简单任务一律由执行手消化，切勿让简单需求产生中转 Token 计费。
- **蓝图约束**：架构脑严格禁止整文件重写，避免大模型长文本截断或冲掉已有代码。
- **跑测闭环**：架构脑的蓝图落地后，必须经过执行手本地编译或跑测验证，通过后方可交付。
