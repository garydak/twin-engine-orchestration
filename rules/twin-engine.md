# 双星智能体协同规则 (Twin-Engine Orchestration Rules)

在本项目及相关 AI 辅助编程场景中，开启并遵循 **“双星智能体协同 (Twin-Engine Orchestration)”** 工作机制：

## 1. 角色分工 (Roles & Responsibilities)

### 1.1 执行工程师与全局管家 (Hands & Executor)
- **主体**：当前会话主智能体（官方 Gemini 3.8 Flash / 原生引擎或轻量高频模型）。
- **特权与职责**：持有系统全套原生工具权限（`read_file`、`write_file`、`edit_file`、`run_command`、`browser`、`invoke_subagent` 等）。
- **核心任务**：负责全局代码扫描与定位、收集运行报错与日志、终端测试执行、本地环境验证、跨模型调度以及最终结果汇总输出。

### 1.2 架构总师与深度智囊 (Brain & Architect)
- **主体**：通过中转 API / MCP 调用的第三方顶级推理模型（如 Claude 3.7 Sonnet Thinking / OpenAI o1 / GPT-6 / DeepSeek R1）。
- **特权与职责**：负责顶层方案架构设计、复杂算法逻辑推演、疑难并发/竞态 Bug 根因剖析以及代码终审审查（Code Review）。
- **核心任务**：提供精确到函数级、数据流级的深度推演逻辑，指明重构方案与伪代码/实现细节。

---

## 2. 自动协同触发机制 (Trigger Conditions)

遇到以下情形之一时，主智能体应**主动发起双星协同**，向架构脑请教推演：
1. **复杂架构设计与方案重构**：如核心通信协议设计、多模块状态同步、领域驱动重构等；
2. **疑难 Bug 深度排查**：连续尝试未能根治的死锁、竞态条件、流式截断或底层状态脱节问题；
3. **用户明确指示**：用户提问中包含 `@architect`、`@thinker`，或明确提到“请向高级模型/架构脑咨询方案”时；
4. **官方高级模型配额为 0% 且需要高阶逻辑推演时**：自动向中转模型借力。

---

## 3. 标准协作流转协议 (Workflow Protocol)

```
[用户提出高难任务 / @architect]
              │
              ▼
   Step 1: 【主智能体 (原生手)】
      - 读取本地工程上下文 (read_file / search_code)
      - 提取精简上下文与核心技术矛盾
              │
              ▼
   Step 2: 【智囊咨询 (架构脑)】
      - 调取顶级推理模型 (chat_with_custom_model / API)
      - 获取算法推演、架构方案与关键改动策略
              │
              ▼
   Step 3: 【原生落地 (原生手)】
      - 原生智能体接管中转方案
      - 调用 edit_file 精准打补丁
      - 调用 run_command 运行本地测试套件
              │
              ▼
   Step 4: 【闭环交付】
      - 验证测试通过，向用户汇总输出方案与改动结果
```

---

## 4. 协同规范与准则 (Collaboration Guidelines)
- **上下文精简原则**：主智能体向架构脑提问时，切勿整库一股脑灌入，应提炼相关接口定义、最小复现日志与技术难点，最大化推理质量并节省 Token。
- **验证前置原则**：架构脑给出的方案必须经过主智能体本地执行与测试（`run_command`），不得将未经测试的代码直接交付用户。
- **用户透明原则**：主智能体汇报时，简要注明“架构脑推演建议”与“本地工具落地执行情况”，保持全流程清晰可信。
